# 移动端 PageSpeed 优化设计

## 背景与目标

2026 年 7 月 1 日的 PageSpeed Insights 实验室报告显示，首页移动端性能得分为 71。主要异常是 FCP 3.3 秒、LCP 4.8 秒和 Speed Index 5.8 秒；TBT 90 毫秒、CLS 0，说明问题集中在首屏可见时机与资源加载优先级，而不是布局稳定性或严重的主线程长任务。

本次目标是在不删除统计和广告能力的前提下：

- 让服务端输出的首屏标题立即可见，不再等待 React 水合和动画执行。
- 降低首页首屏同步 JavaScript 与非关键第三方资源竞争。
- 消除未使用字体和关键字体交换对文本 LCP 的影响。
- 保持现有名称查找、结果展示、SPA 路由统计与广告功能可用。

本次不承诺固定 PageSpeed 分数。验收以代码行为、构建结果和重新测试后的指标变化为准，目标是移动端 LCP 低于 2.5 秒、FCP 低于 1.8 秒，并尽量使性能分数稳定达到 90 左右。

## 设计范围

### 1. 首屏静态渲染

首页标题、说明、输入区域和封面预览在服务端 HTML 中直接以可见状态输出，不设置 `opacity: 0`，也不依赖客户端水合后才显示。

首页不再使用 `motion/react` 实现简单入场动画。生成结果等交互后内容改为普通 React 条件渲染；如需保留轻量视觉反馈，使用不隐藏首屏内容的 CSS 动画，并遵守 `prefers-reduced-motion`。

这样可以直接消除报告中 LCP 标题约 2334 毫秒的元素渲染延迟，并减少首页路由包中的动画运行时代码。

### 2. 非关键统计脚本调度

Google Analytics 和 Microsoft Clarity 不再由服务端直接写入 `<head>`。客户端在页面完成加载后，将初始化安排到浏览器空闲期，并设置约 3 秒的最长等待时间，避免浏览器一直繁忙时统计永远不启动。

调度器必须满足：

- 同一脚本只注入一次。
- 组件卸载时取消仍未执行的任务。
- 浏览器不支持 `requestIdleCallback` 时使用定时器回退。
- 缺少统计标识或非生产环境时不加载。
- 保留现有 `dataLayer`、`gtag` 初始化及 SPA `page_view` 行为。

该策略会牺牲极少量“页面打开后立即关闭”的访问记录，但避免 GA 和 Clarity 在首屏关键阶段争抢网络与 CPU。该取舍已通过方案 A 确认。

### 3. 广告脚本按需加载

AdSense 保留现有生产环境与错误页保护，但从“页面 load 后固定 1.5 秒”调整为非关键空闲任务，不早于首屏关键阶段。

位于页面底部的 Adsterra 原生广告使用 `IntersectionObserver`：广告容器进入视口附近的预加载区后才注入脚本。设计要求：

- 观察区域使用约 400 像素 `rootMargin`，让广告在用户滚动到附近前有加载时间。
- 不支持 `IntersectionObserver` 时采用延时回退，避免广告永久缺失。
- 防止重复注入脚本。
- 组件卸载时断开观察器、取消定时器并清理本组件注入的脚本。

不为广告域名新增 `preconnect`。广告不是首屏关键资源，提前建立连接会与首屏资源竞争。

### 4. 字体与关键样式

删除项目中没有任何实际样式引用的 Libre Baskerville 400/700 引入。

保留现有 Manrope 品牌字体，但把 `font-display` 从 `swap` 调整为 `optional`，让慢速移动网络优先使用系统字体完成首屏绘制，避免字体稍后替换再次推迟文本 LCP。本轮不引入新的字体转换工具，也不手工生成未经验证的 WOFF2 文件。

全局 CSS 体积较小，本轮不实施高风险的手工关键 CSS 内联，避免样式闪烁、缓存失效和 React Router 构建耦合。

### 5. 图片与缓存

图片压缩空间约 33 KiB，且图片不是 LCP 元素，因此不进入本次首要修改。现有图片代理、懒加载和缓存行为保持不变，避免把范围扩展到图片转码基础设施。

图片 WebP/AVIF 转码、响应式尺寸和长期不可变缓存作为后续独立优化处理，需要单独验证 Cloudflare 运行时能力与上游图片更新策略。

## 代码边界

预计修改：

- `app/features/fairy-finder/landing-page.tsx`：移除首屏与结果区的 Motion 依赖。
- `app/features/fairy-finder/components/result-card.tsx`：移除 Motion 依赖。
- `app/components/analytics/GoogleAnalytics.tsx`：改为非关键客户端加载。
- `app/components/analytics/MicrosoftClarity.tsx`：改为非关键客户端加载。
- `app/features/document/index.tsx`：移除 head 内同步统计输出，并复用调度策略加载 AdSense/Pageview。
- `app/features/layout/base-layout/adsterra-native-ad.tsx`：广告临近视口时加载。
- `app/lib/performance/schedule-non-critical-task.ts`：集中实现可取消、带回退的空闲任务调度。
- `app/root.tsx`：删除未使用的 Libre Baskerville 引入。
- `public/fonts/google-fonts.css`：调整字体显示策略。
- `tests/unit/*`：增加调度、重复注入和静态首屏回归测试。
- `package.json`、`pnpm-lock.yaml`：确认项目无剩余 Motion 使用后移除依赖。

不会修改支付、身份认证、数据库、图片代理和公开 API 数据契约。

## 验证策略

采用测试先行：每个行为修改先添加失败测试，再实现最小修复。

自动验证包括：

- 单元测试：空闲调度、回退、取消、脚本去重及缺失配置保护。
- 静态首屏回归：首页源码不再包含首屏 `motion.h1` 或初始透明属性。
- 依赖检查：应用代码不再引用 `motion/react`。
- TypeScript 类型检查。
- 生产构建。
- 构建产物检查：首页路由包不再打入 Motion 运行时代码。
- 敏感信息检查：确认关键环境变量没有新增硬编码，环境文件仍由 `.gitignore` 排除。

部署后重新运行移动端 PageSpeed Insights 3 至 5 次并取中位数。实验室数据改善后，还需通过真实用户数据持续观察 LCP 和广告/统计完整性。

## 对抗性审查重点

完成实现后，主动尝试推翻修改：

- 禁用 JavaScript时，首屏标题与输入区是否仍然可见。
- 水合前后是否出现内容闪烁或属性不匹配。
- `requestIdleCallback` 不存在、永不空闲或组件提前卸载时，是否泄漏任务或永久丢失脚本。
- React 严格模式重复执行 Effect 时，是否注入重复统计/广告脚本。
- SPA 路由第一次和后续切换是否仍能发送正确的 `page_view`。
- 广告容器一直不接近视口时，是否符合“暂不加载”的设计，而不是误判为故障。
- 延迟脚本是否违反现有隐私同意流程；若项目实际上没有同意管理，本次不伪造同意状态，但必须明确记录残余合规风险。
- 包体积下降是否来自真实移除依赖，而不是把代码挪到仍会立即加载的另一个分包。

## 风险与回滚

- 统计脚本延迟可能遗漏极短会话；若业务数据明显异常，可单独缩短最长等待时间，而不恢复 head 内立即加载。
- Adsterra 延迟加载可能降低未滚动到页底用户的广告请求量，这是预期行为，不应通过提前加载回滚性能优化。
- `font-display: optional` 在慢网下可能使用系统字体，造成轻微品牌字体差异，但不会隐藏文本。
- 删除 Motion 会减少入场动画，不改变核心交互和数据结果。

各部分保持独立，可按“首屏渲染、统计调度、广告可见性、字体”分别回滚，避免一次性恢复所有性能问题。
